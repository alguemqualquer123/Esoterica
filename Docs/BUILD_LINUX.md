# Build Linux — Esoterica

Guia rápido para compilar e rodar o Esoterica no Linux (Ubuntu 22.04/24.04, Fedora, Arch) com backend Vulkan.

## Pré-requisitos

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y \
  build-essential clang ninja-build cmake pkg-config \
  libvulkan-dev vulkan-validationlayers vulkan-tools \
  libsdl3-dev || libsdl2-dev \
  libfreetype6-dev \
  libssl-dev libprotobuf-dev protobuf-compiler \
  zlib1g-dev \
  libuuid1 uuid-dev \
  libsqlite3-dev

# Opcional (mas recomendado)
sudo apt install -y renderdoc spirv-tools glslang-tools
```

Outras distros: pacotes equivalentes (`vulkan-devel`, `SDL3-devel`, etc).

**Vulkan SDK oficial** (alternativa ao `libvulkan-dev` do sistema): https://vulkan.lunarg.com/sdk/home

**Dependências já incluídas no repo** (`External/`): `EASTL`, `EABase`, `imgui`, `implot`, `mpack`, `pugixml`, `box3d`, `meshoptimizer`, `concurrentqueue`, `D3D12MemoryAllocator` (não usado no Linux, substituído por VMA via Vulkan SDK), etc. Não precisam instalar.

**DXC (DirectXShaderCompiler)**: o `External/DirectXShaderCompiler` já contém build Linux (`libdxcompiler.so`) se você rodar `utils/hct/build.py` dentro dele, ou use o pacote `dxc` do Vulkan SDK. O CMake tenta `External/DirectXShaderCompiler/lib/x64/libdxcompiler.so` e fallback para `find_library(dxcompiler)`.

## Clonar e preparar

```bash
git clone <repo> Esoterica && cd Esoterica

# Gerar type info / shaders (precisa ter Reflector compilado uma vez no Windows ou cross-compilar)
# Se já existe Code/Base/_Module/_AutoGenerated, pule este passo.
cmake --preset linux-debug
cmake --build build/linux-debug --target EsotericaReflector
./build/linux-debug/x64_Debug/EsotericaReflector -s Esoterica.slnx
```

> Nota: o Reflector hoje depende de `Box3D`/`LLVM` mas é portável. Se `clang`/`LLVM` não estiver em `External/LLVM`, instale `llvm-dev libclang-dev`.

## Compilar

```bash
# Debug (com dev tools, Editor)
cmake --preset linux-debug
cmake --build build/linux-debug --parallel

# Release
cmake --preset linux-release
cmake --build build/linux-release --parallel

# Shipping (sem dev tools, LTO)
cmake --preset linux-shipping
cmake --build build/linux-shipping --parallel
```

Binários em `build/linux-<config>/x64_<Config>/` (ex.: `build/linux-debug/x64_Debug/EsotericaEditor`).

## Rodar

```bash
# Editor (requer Vulkan + SDL3)
./build/linux-debug/x64_Debug/EsotericaEditor

# Engine headless (sem janela, pode rodar sem Vulkan)
./build/linux-debug/x64_Debug/EsotericaEngine

# Tools sem janela (sempre funcionam headless)
./build/linux-debug/x64_Debug/EsotericaResourceCompiler --help
./build/linux-debug/x64_Debug/EsotericaResourceServer
./build/linux-debug/x64_Debug/EsotericaTester
```

Se SDL não estiver instalado, as tools headless ainda funcionam; o Editor/Engine tentarão iniciar mas logarão `SDL_Init failed` e sairão.

## Backend de Render

* **Windows**: `D3D12` (`Code/Base/Render/RHI_Direct3D12.cpp`)
* **Linux**: `Vulkan` (`Code/Base/Render/RHI_Vulkan.cpp`) — esqueleto compilável. O editor abre janela mas ainda não renderiza cena completa; o stub permite compilar e rodar tools.

Para habilitar render completo, complete os TODOs em `RHI_Vulkan.cpp` (instance/device/VMA/swapchain/descriptor/pipelines). O `RHI.h` é agnóstico, então o mesmo `Engine` funciona nos dois backends.

## Troubleshooting

| Problema | Solução |
|----------|---------|
| `Could NOT find Vulkan` | Instale `libvulkan-dev` ou defina `VULKAN_SDK=/path/sdk` |
| `Could NOT find SDL3` | Instale `libsdl3-dev` ou `libsdl2-dev` (fallback automático) |
| `uuid/uuid.h not found` | `sudo apt install uuid-dev` |
| `libGameNetworkingSockets.so not found` | Compile de `External/GameNetworkingSockets` (`cmake . && make`) ou `sudo apt install libGameNetworkingSockets-dev` |
| `freetype: not found` | `sudo apt install libfreetype6-dev` ou aponte `External/Freetype` |

## Estrutura de plataforma

```
Code/Base/Platform/Platform_Win32.*  <-> Platform_Linux.*
Code/Base/Platform/PlatformUtils_*.h
Code/Base/FileSystem/Platform/FileSystem_* + FileSystemPath_*
Code/Base/Threading/Platform/Threading_*
Code/Base/Types/Platform/Types_*
Code/Base/Logging/Platform/SystemLog_*
Code/Base/Math/Platform/Math_*
Code/Base/Application/Platform/Application_Win32.* <-> Application_Linux.* (SDL3)
Code/Base/Imgui/Platform/ImguiPlatform_*
Code/Base/Input/InputDevices/Platform/InputDevice_*_*.cpp
Code/Base/Render/RHI_Direct3D12.cpp (Win) <-> RHI_Vulkan.cpp (Linux)
Code/Applications/Engine/{Win32,Linux}/  Code/Applications/Editor/{Win32,Linux}/
Code/PropertySheets/Esoterica.Win32.props <-> Esoterica.Linux.props
```

CMake detecta plataforma via `if(WIN32) ... elseif(UNIX)` e exclui automaticamente `*_Win32.cpp` no Linux e `*_Linux.cpp` no Windows (`CMakeLists.txt:ee_collect_sources`).

## CI

O preset `linux-*` só é selecionável em hosts Linux (`condition hostSystemName == Linux`). Em runners Ubuntu, use:

```yaml
- run: cmake --preset linux-release && cmake --build build/linux-release
```

## Diferenças conhecidas vs Windows

* `LivePP`, `PIX`, `AGS`, `DbgHelp` desabilitados no Linux (Windows-only).
* Path case-sensitive: `Data/Maps/Foo.map` != `data/maps/foo.map`. O engine força lowercase em Windows mas preserva case no Linux.
* Delimitador: `\` (Win) vs `/` (Linux) — use `FileSystem::Path` sempre.
